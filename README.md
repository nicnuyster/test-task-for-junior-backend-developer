# Планировка задачи

**Условие**
У нас есть API сервиса, который позволяет создавать, изменять, удалять, смотреть таски для пользователей (мед персонала).
Нам необходимо забубенить фичу для добавления повторных задач (раз в день, в месяц, через день, по определенным датам месяца)

**Постановка**
В данном случае сделаем отдельную функцию *CreatePereodic*, которая будет добавлять много задач в нашу БД много задач.

Суть новой функции схожа с уже существующей *Create*, однако нам необходимо добавить переменных в *CreateInput*, добавлять несколько столбцов в БД, изменить response.

1) Реализовать *CreatePereodic* копию метода *Create*
2) Добавить и реализовать в *CreatePereodic* 1 дополнительную переменную
3) Реализовать цикличное создание задач *CreatePereodic*
4) Дополнить реализацию условиями для цикличного создания

**Принцип открытости закрытости**
Т.к. новый func отвечает принципу открытости\закрытости SOLID (только добавили необязательных переменных, возможность создать 1 задачу осталась). 
Однако у меня сложилось впечатление, что новую func нужно именно добавить, а не заменить.

**Дополнительно**
Т.к. у нас будет добавляться много задач, нам нужны функции, которые будут
1) Обновлять
2) Удалять
задачи с одинаковыми именами и\или описаниями. Т.к. если вдруг сроки\описание задачи поменялось со временем,
хорошо иметь возможность удалить\изменить оставшиеся задачи.

**Так же:** 
1) Новая функция должна работать с уже существующим форматом *task*
2) Кол-во столбцов в БД должно остаться неизменным
3) Не допустимы изменений в работе или структуре уже существующих структур\функций\классов 

# Реализация

**Реализация функций CREATE** изменение - добавление в *CreatePereodic* дополнительно входного поля int, при передаче которого *title* задачи будет изменяться, для наглядности внесенных изменений. 

Было решено добавить 4 переменных в структуру входных данных *CreatePereodicInput* в *ports.go*:
1) *Repetition* - кол-во повторений, где целые числа - кол-во повторений.
значения не строго > 0. Так же планировалось добавить вычисление кол-ва повторений до конца месяца (значение: -1) и до конца года (значение: -2), однако я отказался от этой идеи т.к. сначал нужно завершить задачу и вообще хз хорошая это идея или нет, что-то дополнительно вычислять на беке.
2) *RecurrType* - как мы будем повторять наши задачи, через N день, каждый 2й день, каждый месяц
3) *DayAmount* - для повторение через N дней нужно указать через сколько дней.  
4) *StartDate* - начальная дата, указывает с какого числа должна начаться задача. 

Для работоспособности реализации необходимого функционала в *service.go* можно заметить существенные добавления в следующих файлах:

1) **service.go** основная логика для создания задач в *func CreatePereodic* и в *func validateCreatePereodicInput*, *func NextPereodicOcurrence*
2) **ports.go** создан *struct CreatePereodicInput* - вид входных данных
3) **taskhandler.go** создан *func CreatePereodic*
4) **dto.go** создана *taskMutationPereodicDTO struct* - для правильного передачи данных
5) **router.go** создана *api.HandleFunc* с новым путем *"/tasks/batch"* т.к. нельзя несколько одинаковых методов положить в 1 путь
6) **task_repository.go** создана *func CreatePereodic* для добавления данных в бд
7) **openapi.json** созданы, *"/api/v1/tasks/batch"* с новым *post* и *schema* с *"CreatePereodicTaskRequest"* для того, чтобы правильно принять входные данные.

**Реализация функций DELETE и UPDATE**
Причина добавления данных функций - удаление\обновление последующих задач. Т.к. кол-во задач может быть много и некоторые из них могли оказаться неактуальными\ненужными. 
*Например:* Задача по послепроцедурной отчистки оборудывания. В клинику может прибыть дополнительное оборудывание, что следовало бы отразить в описании задач.

Для роботоспобности *func DeletePereodic* *func UpdatePereodic* помимо заполнения интерфейсов нужно обновить *SQL query* для нашей БД и редактировать *openapi.json*, т.к. поля *id* нет в моем пути.

**Поле ID в openapi.json**
дополнительные структуры в *dto* и в *ports*.

**Изменения в SQL query**
В условии *WHERE id >= $5 AND title = (SELECT title FROM tasks WHERE id = $5)*
Для удаления\обновления задач необходимо не только просмотр задач по *ID*, но и по *title*, т.к. в данном случае по *ID* мы не узнаем какая именно это задача, нам нужно другое уникальное поле, а в данном случае - *title*.
Это нужно для поддержания 2й нормальной формы, чтобы небыло аномалий удаления.
